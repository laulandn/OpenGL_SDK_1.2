Name    color_subtableName Strings    ARB_imagingVersion    $Date: 1997/12/18 21:33:03 $ $Revision: 1.2 $Dependencies    OpenGL 1.2 is required    EXT_texture_color_table affects the definitionOverview    This extension allows a portion of a color table to be redefined, and    defines a method to load a portion of a color lookup table from the    framebuffer.New Procedures and Functions    void ColorSubTable(enum target,		       sizei start,		       sizei count,		       enum format,		       enum type,		       const void *data);    void CopyColorSubTable(enum target,			   sizei start,			   int x,			   int y,			   sizei width);New Tokens    None.Additions to Chapter 2 of the 1.0 Specification (OpenGL Operation)    NoneAdditions to Chapter 3 of the 1.0 Specification (Rasterization)    The specification of color lookup tables is added to the GL    Specification in section 3.6.2, "Pixel Transfer Modes." A portion    of a color table is redefined using the ColorSubTable command    with <target> set to COLOR_TABLE, POST_CONVOLUTION_COLOR_TABLE,    POST_COLOR_MATRIX_COLOR_TABLE, or TEXTURE_COLOR_TABLE_SGI.    <start> and <count> control which entries of the color table    are changed. If <start> + <count> exceeds the number of entries in    the table then an INVALID_VALUE error is generated. <format> and    <type> have the same meaning as for ColorTable.  The data is treated as    a 1D texture just as in ColorTable.    A portion of a color table can be re-defined using image data in the    framebuffer.  CopyColorSubTable accepts image data from a <width> pixel    wide by one pixel high color buffer region whose lower-left pixel has    window coordinates <x>,<y>.  If any pixels within this region are    outside the window that is associated with the GL context, the values    obtained for those pixels are undefined.    These pixel values are obtained from the framebuffer exactly as if    ReadPixels had been called with <format> set to RGBA, with processing    continuing through Conversion of RGBA values.  At this point all pixel    component values are treated exactly as if ColorTable had been called,    beginning with the scaling of the color components by COLOR_TABLE_SCALE.    The accepted values of the <target> parameter are COLOR_TABLE,    POST_CONVOLUTION_COLOR_TABLE, POST_COLOR_MATRIX_COLOR_TABLE or    TEXTURE_COLOR_TABLE_SGI.Additions to Chapter 4 of the 1.0 Specification (Per-Fragment Operationsand the Framebuffer)    NoneAdditions to Chapter 5 of the 1.0 Specification (Special Functions)    NoneAdditions to Chapter 6 of the 1.0 Specification (State and State Requests)    NoneAdditions to the GLX Specification    NoneGLX Protocol    Two new GL commands are added. The first command has pixel data, and is    sent to the server either as part of a glXRender request or a    glXRenderLarge request:	ColorSubTable	    2		44+n+p		rendering command length	    2		??		rendering command opcode	    1		BOOL		swap_bytes	    1		BOOL		lsb_first	    2				unused	    4		CARD32		row_length	    4		CARD32		skip_rows	    4		CARD32		skip_pixels	    4		CARD32		alignment	    4		ENUM		target	    4		INT32		start	    4		INT32		count	    4		ENUM		format	    4		ENUM		type	    n		LISTofBYTE	table	    p		unused, p=pad(n)	If <count> < 0, <format> is invalid or <type> is invalid, then the	command is erroneous and n=0. The structure of <table> is described	in Appendix A of the GLX Protocol Specification, "Pixel Data", using	the parameters <swap_bytes>, <lsb_first>, <row_length>, <skip_rows>,	<skip_pixels>, <alignment>, <format>, and <type> as given in the	request, a width of <count>, and a height of 1.    The second command is sent to the server as part of a glXRender request:	CopyColorSubTable	    2		24		rendering command length	    2		??		rendering command opcode	    4		ENUM		target	    4		INT32		start	    4		INT32		x	    4		INT32		y	    4		INT32		widthDependencies on EXT_texture_color_table    If EXT_texture_color_table is not supported then the following values    for <target> are invalid when calling ColorSubTable or    CopyColorSubTable: TEXTURE_COLOR_TABLE_SGI.Errors    INVALID_ENUM is generated if ColorSubTable or CopyColorSubTable    parameter <target> is not one of COLOR_TABLE,    POST_CONVOLUTION_COLOR_TABLE, POST_COLOR_MATRIX_COLOR_TABLE, or    TEXTURE_COLOR_TABLE_SGI.    INVALID_ENUM is generated if ColorSubTable parameter <format> is not    RED, GREEN, BLUE, ALPHA, RGB, RGBA, ABGR_EXT, LUMINANCE, or    LUMINANCE_ALPHA.    INVALID_ENUM is generated if ColorSubTable parameter <type> is not BYTE,    UNSIGNED_BYTE, SHORT, UNSIGNED_SHORT, INT, UNSIGNED_INT, or FLOAT.    INVALID_VALUE is generated if ColorSubTable or CopyColorSubTable    parameter <start> exceeds the size of the table.    INVALID_VALUE is generated if the ColorSubTable parameters <start> +    <count> exceed the size of the table.    INVALID_VALUE is generated if the CopyColorSubTable parameters <start> +    <width> exceed the size of the table.New State    NoneNew Implementation Dependent State    None
